## Imports and template formats

The package is a v2 addon with `dist` JavaScript and declarations. Build exports
and app reexports are generated by Rollup; non-icon component/modifier/service
paths are also listed in `ember-addon.app-js`.

```gjs
import AuButton from '@appuniversum/ember-appuniversum/components/au-button';
import AuInput from '@appuniversum/ember-appuniversum/components/au-input';
import { on } from '@ember/modifier';

// Use these imported bindings in a .gjs/.gts <template>.
```

In conventional resolver `.hbs`, `<AuButton>` and `<AuInput>` use app reexports.
Strict templates require lexical imports, including helpers/modifiers (`on`,
`fn`, etc.) that conventional templates resolve globally. TypeScript apps may
use the public template-registry integration if needed; follow their existing
setup instead of adding a second type system.

The addon's tests import `#src/components/au-input.gts`. **Do not copy `#src` or
source `.gts` extensions into consuming-app package imports**: those are local
source/testing conventions, while consumers use the package's public export
paths. `src/private` is not a supported application API even if a broad export
pattern makes some implementation modules reachable.

Icons are named imports, e.g. `{ AddIcon }` from
`@appuniversum/ember-appuniversum/components/icons/add`. They are generated at
build time and are not global resolver components. Verify other export names
in the built installed package.

## State, DOM events, and callbacks

Use app-owned tracked state and value-down/action-up for modern components:

```gjs
import Component from '@glimmer/component';
import { tracked } from '@glimmer/tracking';
import { fn } from '@ember/helper';
import { on } from '@ember/modifier';
import AuInput from '@appuniversum/ember-appuniversum/components/au-input';
import AuCheckbox from '@appuniversum/ember-appuniversum/components/au-checkbox';
import AuButton from '@appuniversum/ember-appuniversum/components/au-button';

export default class FilterControls extends Component {
  @tracked query = '';
  @tracked activeOnly = false;
  setQuery = (event) => { this.query = event.target.value; };
  setActive = (checked) => { this.activeOnly = checked; };
  resetQuery = (value) => { this.query = value; };

  <template>
    <AuInput aria-label="Zoeken" value={{this.query}} {{on "input" this.setQuery}} />
    <AuCheckbox @checked={{this.activeOnly}} @onChange={{this.setActive}}>Enkel actief</AuCheckbox>
    <AuButton {{on "click" (fn this.resetQuery "")}}>Wis zoekterm</AuButton>
  </template>
}
```

`fn` curries values; it does not convert a DOM Event into text. Use native
attributes (`type`, `id`, `name`, `value`, `required`, `readonly`) where the
component forwards them. Do not add `@onInput`, `@onClick`, `@value`, or
`@onChange` indiscriminately. See forms.md for the distinct callback shapes.

The data-table family is still classic Ember. Pagination/search/sorting mutate
`page`, `filter`, `currentSorting` and selection via classic setters/aliases.
Match an existing app's query-param and `{{mut}}` usage rather than pretending
these accept modern `@onPageChange`/`@onSort` callbacks. Verify state write-back
with a rendering test; do not use mut as the universal pattern for modern
Glimmer components. In strict templates import `mut` from `@ember/helper` when
that legacy binding is required.

## Yielded blocks and attribute targets

| Component                      | Yield / naming                                                        |
| ------------------------------ | --------------------------------------------------------------------- |
| AuToolbar                      | Direct `Group` component                                              |
| AuList / AuTabs / AuPanel      | Direct `Item` / `Tab` / `Section` component (local alias arbitrary)   |
| AuCheckboxGroup / AuRadioGroup | Hash keys `Checkbox` / `Radio`                                        |
| AuMainContainer                | Separate hashes with lowercase `sidebar` and `content`                |
| AuCard                         | Separate lowercase `header`, `content`, `footer` hashes               |
| AuFieldset                     | Separate lowercase `legend` and `content` hashes                      |
| AuTooltip                      | Hash with `target` modifier, `Content` component, `isShown`           |
| AuModal                        | Named `title`, `body`, `footer` OR contextual `{ Body, Footer }`      |
| AuTable                        | Named `title`, `header`, `body`, `footer`                             |
| AuDataTable                    | Separate `menu`/`content` hashes plus table as second block parameter |

Do not change key case or combine named/contextual modal modes: **any named
modal block switches off contextual yields**. Separate-yield components depend
on absent contextual keys being harmless in their intended composition; copy
patterns from their tests and do not destructure a nonexistent all-at-once hash.

Attribute forwarding is not uniform: AuInput forwards to input; AuCheckbox,
AuRadio and AuToggleSwitch forward to their input inside a wrapping label;
AuDatePicker forwards to the Duet host; AuTable forwards to table;
AuDropdown forwards to its outer div. AuTooltip and AuTimePicker do not forward
a root attribute bag. Inspect templates before relying on event/ARIA placement.

## Public modifiers

- `au-date-input`: named `value` (ISO date string/Date), `prefillYear` boolean
  (false default), `onChange(isoDate|null, Date|null)`. Applied to an input;
  uses Inputmask, updates native value, and removes the mask on destruction.
  Prefer AuDateInput unless decorating an existing native input is intentional.
- `au-inputmask`: named `options` object passed to Inputmask; teardown removes
  the mask. No positional arguments or value/change callback contract here.
  Verify options against the app's installed Inputmask version.

```hbs
<input
  id="reference"
  aria-label="Referentienummer"
  {{au-inputmask options=this.referenceMaskOptions}}
/>
```

Strict-template imports are
`@appuniversum/ember-appuniversum/modifiers/au-inputmask` and
`…/modifiers/au-date-input`. Internal floating-ui and tooltip modifiers are not
public extension APIs.

## Toaster service

Mount `<AuToaster />` in the shell. Inject the app-reexported service:

```js
import { service } from '@ember/service';
// Inside the consuming component/controller:
@service toaster;
// After a successful operation:
// this.toaster.success('Uw wijzigingen zijn bewaard.', 'Opgeslagen', { timeOut: 5000 });
```

Verified methods: `notify(message,title,options)`, `success(...)`, `warning(...)`,
`error(message?,title?,options)`, `loading(message?,title?,options)`,
`show(Component,options)`, `close(toast)`. The argument order is **message,
title**, not the reverse. Options: `icon`, `closable`, `timeOut`, and built-in
`type` (alert skin). Default `timeOut` is null (persistent), `closable` true;
a truthy timeout uses milliseconds. Store the returned toast to close/replace a
loading notification rather than leaving it permanently visible.

`show` takes a component value, not a resolver string. A custom component
receives `@options` and `@close`; it owns its content and accessibility. The
service exports types including `BaseOptions`, `ToastOptions`,
`CustomToastSignature`, and `ToastData` for typed consumers.

## Modal integration and focus

```hbs
{{! Container must exist before the modal is constructed. }}
<AuModalContainer />
<AuButton {{on "click" this.openDialog}}>Dossier verwijderen</AuButton>
<AuModal
  @id="delete-record"
  @title="Dossier verwijderen"
  @modalOpen={{this.dialogOpen}}
  @closeModal={{this.closeDialog}}
  aria-label="Dossier verwijderen"
>
  <:body><p>Deze actie kan niet ongedaan worden gemaakt.</p></:body>
  <:footer>
    <AuButton
      @skin="secondary"
      {{on "click" this.closeDialog}}
    >Annuleren</AuButton>
    <AuButton
      @alert={{true}}
      {{on "click" this.confirmDelete}}
    >Verwijderen</AuButton>
  </:footer>
</AuModal>
```

The app actions manage a tracked boolean; `closeDialog` must set it false.
The component uses ember-focus-trap, initially targets `.au-c-modal__title`,
and supports `@initialFocus`. Escape requests closure unless `@closable=false`;
it does not deactivate the trap while open state stays true. It accounts for
`#ember-basic-dropdown-wormhole` when present. Use a unique @id, verify focus
return to the opener and prevent unintended background interaction. The source
sets role=dialog and aria-describedby, but not an automatic aria-labelledby or
aria-modal guarantee. Supply a meaningful name and test the actual interaction.

## Testing approach

The addon uses QUnit, ember-qunit `setupRenderingTest`, qunit-dom, and
`@ember/test-helpers` (`render`, `click`, `fillIn`, `triggerKeyEvent`, `settled`,
etc.). Most tests are `.gts`/`.gjs` with inline `<template>` and source imports.
`tests/test-helper.ts` uses `ember-strict-application-resolver`, registers toaster
and file-queue services and third-party loose-mode modules, and imports SCSS.
Consumers should use their own established resolver/test setup, not copy this
entire harness. Conventional apps may use `.hbs` fixtures/hbs-tag rendering.

Example consuming-app rendering test (strict `.gts`):

```gts
import { module, test } from 'qunit';
import { setupRenderingTest } from 'ember-qunit';
import { click, render } from '@ember/test-helpers';
import { tracked } from '@glimmer/tracking';
import AuCheckbox from '@appuniversum/ember-appuniversum/components/au-checkbox';

class State { @tracked checked = false; }
module('Integration | notification preference', function (hooks) {
  setupRenderingTest(hooks);
  test('the label toggles app-owned state', async function (assert) {
    const state = new State();
    const update = (checked: boolean) => { state.checked = checked; };
    await render(<template>
      <AuCheckbox @checked={{state.checked}} @onChange={{update}}>Meldingen</AuCheckbox>
    </template>);
    await click('label');
    assert.true(state.checked);
    assert.dom('input').isChecked();
  });
});
```

Add tests for wrapper contracts rather than only asserting component existence:
label/description/error associations, callback payloads, disabled/loading states,
modal close/Escape/focus restoration, keyboard menus/tooltips, and data-table
query updates. Use a real browser for focus/layout/zoom and Duet interactions.
The addon includes Storybook accessibility tooling in docs-app, but no automatic
accessibility pass can replace interaction tests. Do not claim axe is installed
or introduce it without checking the app first.

## Actual commands

Read the target package's scripts before choosing a command:

```sh
# Root workspace (runs across packages):
pnpm lint
pnpm test
# Focused addon:
pnpm --filter @appuniversum/ember-appuniversum lint
pnpm --filter @appuniversum/ember-appuniversum test
pnpm --filter @appuniversum/ember-appuniversum build
# Docs app's Ember tests:
pnpm --filter docs-app test:ember
```

Addon lint includes Prettier, template lint, ESLint, publint, and ember-tsc.
Addon tests build via Vite and run Testem; they need installed dependencies and
a configured browser. Icon generation (`build:icons`, included in `build`)
is needed when generated source icons are absent. A clean clone without
node_modules cannot run these meaningfully without dependency installation.
Report limitations; do not imply a Markdown validation pass ran Ember tests.
